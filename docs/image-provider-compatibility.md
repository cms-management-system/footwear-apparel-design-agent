# 图片接口兼容与恢复验收（2026-10-08）

## 用户问题与范围

恢复线上服务时，图片服务拒绝原模型 gpt-image-2-all。切换其同步接口支持的 gpt-image-2-pro 后，HTTP 200 返回 data[0].url，原客户端仅接受 b64_json，导致真实生成的图片无法保存。修复目标是让既有设计出图继续可用，不改变设计确认与视觉检查规则。

## 数据契约

图片服务 POST /images/generations 必须返回恰好一张图片。优先读取原有 data[0].b64_json；缺少该字段时，可读取 data[0].url。

URL 仅接受 HTTPS、默认端口、无用户名密码，并且域名必须与服务器配置 AGENT_IMAGE_DOWNLOAD_HOSTS 的某项完全一致（逗号分隔，不支持通配符，默认空）。下载不发送模型密钥、不跟随重定向，最大 10 MB，随后仍由既有图片校验和归一化流程处理。下载失败沿用 IMAGE_OUTPUT_INVALID，保留调用记录，不自动再次生图。

当前图片服务使用 images-2.ai-tudou.net；这是私有运行配置，不应把任意返回域名自动加入允许名单。生成结果保存在本地持久化资产目录，不把临时服务商链接当作永久结果。

## 验收标准

- 原有 Base64 图片响应继续可用。
- 允许域名 URL 响应可下载；下载请求不携带 Authorization。
- 非允许域名、HTTP、附带用户名密码、其他端口、重定向、超过大小限制均失败。
- 真实设计任务保存图片、完成逐项检查；重启后图片哈希与记录保持一致。
- 图片协议兼容不代表视觉质量已达到企业生产标准，仍需人工确认。

## 本次验收结果

后端 130/130 通过，新增 12 项图片响应兼容测试。云端生成的 1024×1024 白色长袖衬衫图片已保存，视觉目标与约束均通过，确认操作 HTTP 200。实际整机重启后确认状态和图片哈希保持一致。测试素材及需求为合成验收，不证明真实销售或企业生产质量。
